One rule to ask about at the opening

The Pizza Cup rules say hard-coded trajectories are not allowed in scored autonomous behavior. Supporting infrastructure is allowed. If HackLab #2 copies that rule, taught primitives become a fallback and the learned policy has to carry the scored task. Ask a NormaCore mentor before you plan around primitives.

NormaCore reposted the HackLab announcement three weeks ago with "More details soon". The real brief should come at the 09:30 opening. June teams built on Station beta.8. You will most likely get beta.10.

04 · Reading their posts

What NormaCore focuses on, and the one thing they push

The one thing

Station, the open-source data layer for Physical AI

Every channel repeats it. One runtime that unifies robot SDKs and records full-fidelity data from any fleet. NormFS is the storage engine under it. Their stated end goal is a shared model that improves with every hour a robot runs.

The way in

ElRobot

The 3D-printed 7+1 DOF arm is what gets attention. Its launch post in February is still pinned on X. It exists so people record demonstrations into Station.

Team 4's patch sets STATE_DIM and ACTION_DIM from 6 to 8 in train.py and passes motor ids 1 to 8. I overstated this problem in the first version of this page.

Ranked

1

Record to deploy is full of silent traps

Each step works in isolation and fails quietly when joined. Team 2 never got a usable checkpoint and built around it. Team 4 got through and logged every trap. Nothing in the official docs collects them in one place. Whoever turns this into a clean, repeatable path solves the problem the new track format is built on.

Source: Team 4 LESSONS.md, Team 2 README, Pizza Hackathon starter README
2

The policy only works near what it saw

Team 4's arm would not move at all from a parked pose, because the stock runner aborts a whole tick when any joint is too far from its target. Same start pose, same lighting, same camera framing as the demos. This is where a supervisor that watches and corrects earns its place.

Source: Team 4 LESSONS.md
3

No official way for an agent to talk to Station

Three of the four known June teams wrote their own MCP server. Team 4 first guessed the API from the task sheet and got it wrong. The viewer chat prototype has sat unmerged since June 8.

Source: June spotlight posts, Team 2 and Team 4 repos, PR #52
4

Calibration and gripper

Auto-calibration can collide with the table depending on the starting pose (#112). The gripper stalls under load during mirroring and inference (#101). Start from a safe pose and pick light objects that are easy to grip.

Source: GitHub issues
5

Smaller traps

Torque must be enabled before goal writes do anything. There is no "get frame" call, you follow a camera queue and keep the latest entry. The dataset video tool crashes when a dataset holds only one video (#103). The ElRobot URDF has an invalid mass (#92). Intel Macs are not supported yet (#145). Apple silicon is fine.

Source: Team 4 LESSONS.md, GitHub issues and pull requests

Saturday morning checklist, from Team 4's log

  • Connect to Station on port 8888
  • Enable torque before the first move
  • Clamp to each motor's calibrated range
  • Two cameras, on separate USB controllers or a powered hub
  • Check the camera queues deliver frames, not only the web UI
  • Pin the servo bus to the follower arm
  • One task sentence, identical at recording and inference
  • About 50 demos, around 5 positions with 10 each
  • Train with unbuffered logs and at least 12 data workers
  • Start every rollout near the demo start pose
06 · So what

What this means for your build

Agent plus policy has been done once, by the winner. A policy with visual checks won in Cologne. Nobody has closed the loop yet: the supervisor catches a failure, tags it in Station, and that data makes the next policy better. That is still the open spot, and it is NormaCore's own pitch.

LAYER 1 · MUST HAVE

Safe control

Station MCP server. Limits in the server. Taught poses Claude can call. Team 2's public repo shows one way to shape the tools.

Demo: "Put the red block in the cup."
LAYER 2 · NOW REALISTIC

Learned skill

Follow Team 4's path: about 50 demos, the 2-line patch, a Nebius job, walk mode at deploy. Start recording early.

Demo: the same task, run by the policy.
LAYER 3 · THE DIFFERENCE

Failure loop

Claude watches the policy, steps in when it stalls or misses, and tags the episode in Station as success, failure or correction.

Demo: knock the block away. It notices, recovers and saves the failure as training data.

A possible 30-hour plan

Set up, two cameras, calibrate
Record about 50 demos
Layer 1: MCP, limits, taught poses
Train on Nebius
Layer 2: deploy the policy
Layer 3: failure loop and tagging
Sleep in shifts
Retrain with the tagged failures
Rehearse three demos, film the hero run
Freeze code, pitch, submit by 17:45
